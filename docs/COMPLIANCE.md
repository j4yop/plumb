# Compliance, rule by rule

The organisers' clarification email puts the burden on the team:

> *"Each team is responsible for making sure that its particular project, tool, platform or dataset
> complies with the competition rules. As a reference, **anything that is not explicitly allowed is
> not permitted**."*

That is a strict-construction clause, so this page does the only thing that answers it: it lists
every prohibition, says what this repository does about it, and gives the command that checks the
claim. Nothing here is a promise; all of it is verifiable from the committed code.

## The four prohibitions

| Prohibition | What this repository does | How to check |
|---|---|---|
| **Checking the output against the video** | The video is **not in the decision path and not in the checking path**. No frame of it was used to accept or reject a label. The homography is used only to turn the provider's normalised coordinates into metres. | `grep -rn "\.mp4\|cv2\|ffmpeg\|imageio\|VideoCapture" src/` → nothing: no code opens a video. `asset_paths()` lists four files and none is the video. |
| **Hand labels, human-produced data, or anything created manually on the provided game** | Every label is computed. There is no handwritten annotation of the provided match anywhere, for training or for validation. | `git ls-files` — no `.csv`, `.json` or `.npy` data file is tracked. The only per-frame file in the repository is generated by `make reproduce`. |
| **Uploading the provided data to AI services** | The pipeline has **no network code at all**. It runs on numpy and the standard library. | `grep -rn "urllib\|requests\|socket\|openai\|anthropic" src/ --include=*.py` → nothing |
| **Training, fitting or calibrating on the ground-truth possession data or the video** | There is **no training** — the system has no model and no fitted parameter. Every threshold has a derivation that touches neither. | `docs/adr/0008-parameters-are-tuned-on-external-data.md`; `make external`; `make stability` |

## The four permissions, and where we use them

| Permission | Where it is used |
|---|---|
| **Running automatic checks using only the provided data** | The label-free stability criterion (`make stability`) runs on the provided *tracking* and no labels at all. The agreement check against the Smart Tagging (`plumb ask "do we agree with the smart tagging"`) runs on provided data. |
| **Inspecting the provided data and the video to better understand what counts as possession** | Used for exactly that: reading what the organisers' `D` and `H`/`A` mean. Two findings came from it and are recorded in ADR 0004 — that `D` is not "the ball is not tracked", and that possession changes happen when the ball is 2–7 m from the new owner. |
| **Using the tracking, the smart tagging or any other generated data as input** | All three are inputs: `src/mtah/match.py` loads the tracking, the metadata and the Smart Tagging; `src/plumb/phases.py` reads the whole tactical annotation as a first-class input. |
| **Providing files of intermediate steps** | `artifacts/trace.csv` (per-frame evidence), `artifacts/run_report.json`, and `plumb ask --json`, which emits the whole evidence packet for a claim. |
| **Using any dataset you have the rights to use** | Metrica Sports' public sample data. See the licence note below. |

## The licence note

The email adds: *"Please check the license of any dataset before using it."* So, precisely:

**Metrica Sports sample data** (`github.com/metrica-sports/sample-data`) is used for one purpose:
to confirm that the thresholds are not a fit to the provided match. It is not redistributed — no
file from it is in this repository or in the submission.

Its position, checked rather than assumed:

- the GitHub repository declares **no licence file** (`"license": null`), which means default
  copyright — we therefore do **not** redistribute it, and we do not;
- its README publishes the data "to provide some sample data to play around with to the broader
  football analytics community", and asks: *"If you use it for anything public, please acknowledge
  the source"* — the acknowledgement is in ADR 0008 and in `scripts/external_tuning.py`;
- the data is downloaded directly by the reviewer from the public repository; nothing is bundled.

**What happens if that dataset is set aside.** This matters, so it is stated plainly: only one
shipped value leans on the external sweep, and it would not change.

| parameter | if the external data were unavailable |
|---|---|
| `control_radius_m` = 2.0 | unchanged — set by the football definition of control (a ball within about two metres is under a player's control), which the sweep confirms but does not determine |
| `min_control_frames` = 25 | unchanged — set by the label-free stability criterion on the **provided tracking** |
| `handover_margin_m`, `min_dwell_frames`, `min_spell_frames`, `dead_movers`, `dead_onset` | unchanged — a football statement, or an insensitivity that the sweep merely reports |

## One thing the annotation cannot do

It would be convenient to say the Smart Tagging settles the control radius, because the annotation
is provided data and checking against it is explicitly allowed. **It does not, and the measurement
says so.** Sweeping the radius against the 140 mirror pairs:

| control radius | agreement over labelled frames | agreement counting abstention as wrong |
|---:|---:|---:|
| 1.0 m | 81.9 % | 73.6 % |
| 2.0 m (shipped) | 77.6 % | 70.3 % |
| 3.0 m | 74.2 % | 67.4 % |

The agreement **rises as the radius shrinks**, because a smaller radius produces stickier ownership
— it changes hands less often — and a coarse 20-to-50-second annotation rewards exactly that. Using
it to choose the radius would be fitting a metre-scale parameter to a tens-of-seconds label, which
is the same error as fitting to the public window.

The annotation is therefore used for what it can bear: a check on **who had the ball**, at the
resolution of a phase (ADR 0009). Not the resolution of a metre.

## What is not claimed

- The system has not been checked against the video, and no claim in this repository rests on it.
- The public five minutes have not been used to choose anything (ADR 0004). The one configuration
  that had been is documented in ADR 0008 as a correction, and it scored *lower* than the shipped
  one, so dropping it cost nothing.
- The ten-match dataset has not been seen. Nothing here claims otherwise.
