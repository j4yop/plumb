🎯 The pick

Build ANSWERABLE — a certified capability map for automatic football tracking.

“Not another chatbot. A system that tells you which questions this match's data can actually answer, answers them with proof, and refuses the rest — with the exact frames, the coverage behind them, and what would be needed to close the gap.”

1 · Reliability engine

Per-frame quality model of the automatic tracking — ball visibility, ball-out-of-pitch, player-count anomalies (>22 = duplicate tracks), slot churn, speed spikes, homography error. Emits a coverage map and a classified list of unrecoverable gaps. Validated by in-silico error injection: add known noise, measure which conclusions die.

2 · Verified fact library

~40 deterministic tactical facts on top of our own Phase-1 possession engine. Each fact is a defensible coach-facing call carrying value, evidence frames, coverage basis, confidence band, and the question it answers. Aspect-agnostic — possession, restarts, pressing, build-up, defending, transitions, chance creation — so it survives whatever the 26 Nov briefs name.

3 · Router, not author

Local intent router (a model, if any, classifies the question only) → fact ID → deterministic renderer → deterministic refusal gate. The model never touches a tracking row and never writes a claim. Fully local: nothing leaves the machine, which satisfies the Terms & Conditions outright.

Descope path

If week 9 slips: ship ANSWERABLE-minus-router — reliability engine + fact library + templated front end. Still a product, still a thesis, still demoable. If the briefs name a decision-shaped aspect: re-point the fact library; the engine and refusal machinery do not change.

🔎 The three findings that changed the answer

1 · The “40% blind spot” headline was inflated — and an advisor caught it

40.69% of graded frames lack a tracked ball, but the genuinely unrecoverable gaps are two stoppages (~6 minutes, ~7% of the match); much of the rest is the ball off the pitch or in a keeper's hands, and the halftime “94% ball present” is a warm-up false positive. Do not sell “the tracker loses the ball 40% of the time” — sell the classification: which absences are benign, which are structural, and what each does to the claims you want to make. Honest numbers are more credible to a jury.

2 · The unit of value is a question, not a metric

The real product property is which questions this automatic tracking can support at all. That reframing is what makes one candidate coherent and leaves two half-built. It is the spine of ANSWERABLE.

3 · The real gate is the selection funnel — and nobody modelled it

Two gates decide whether we reach the jury: Phase 1's automatic ranking (top 20) and an unnamed Phase 2 evaluation cutting 20 → 5. All five advisors scored projects against a proxy rubric for the March jury and treated Phase 2 as mere build time. Corrections: the horizon is 14 weeks, not 7 (26 Nov → 2 Mar), every candidate must score twice — as a live pitch and as a standalone re-runnable artefact — and gate-legibility is now an explicit rubric line.

🏗 Architecture

raw ATD + Smart Tagging + event data + homography
        │
        ├──▶ RELIABILITY ENGINE ──▶ coverage map · anomaly list · classified gaps
        │        (deterministic)      in-silico error-injection study
        │
        ├──▶ POSSESSION / SPELL ENGINE (our Phase 1 system) ──▶ fact + uncertainty
        │
        ├──▶ TACTICAL FACT LIBRARY (deterministic, ~40 facts, aspect-agnostic)
        │        possession · restarts · pressing · build-up · defending · transitions · chance creation
        │
        └──▶ ROUTER (local, intent only) → FACT ID → DETERMINISTIC RENDERER → REFUSAL GATE
                 no tracking row ever reaches the model · nothing leaves the machine

Fact schema (frozen day 1): id · question · value · unit · evidence_frames · coverage_basis · confidence_band · decision_phrasing · dependencies. Every fact must be answerable as a call and must declare its weakest dependency, so the refusal gate can reason about it.

Refusal gate: if the coverage basis for a fact's supporting segment is below threshold the system does not answer — it returns what is missing, which frames, what would fix it, and the nearest answerable proxy. Refusal is a feature with its own screen.

Smart Tagging is a prior, not a label: 638 instances, mirror-paired attack/defence codes with opposite teams, file order grouped by code (sort by start), set-piece windows of 5 s / 35 s (windows, not instants), every throw-in tagged N/A. Phase-2 event data validates facts; it never creates labels.

🎬 The 5-minute live demo

  1. 0:00 Coach asks “Where did we lose the ball most in the second half?” → the number, the frames, a confidence band, and a coverage strip under the answer.
  2. 0:45 Scrub the coverage map: halftime warm-up flagged, two stoppages flagged as unrecoverable, the 138.6 s blackout shown with its duration.
  3. 1:30 Ask what the data cannot support: “Which midfielder mis-positioned before the goal?” → refusal: no player identities; the ball is untracked for minutes around the goal. Here is exactly what is missing, here is what would fix it, here is the closest answerable proxy (team-level spatial shift).
  4. 2:30 Cross-match capability map: the same question across the 10 Phase-2 matches — answerable in 6 of 10; the coverage strip explains the other 4.
  5. 3:30 Robustness: injected noise → which conclusions survive, which die.
  6. 4:30 The meta-moment: “Every number here was computed by deterministic code from the raw tracking. The language model only understood the question. Nothing left this machine.”
