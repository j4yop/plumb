⚡ Critical Clashes & Trade-offs

  • #8 vs #12. A and C back #12 (tactical-moment engine over the 638 Smart Tagging instances); B, D and E back #7/#8 with a continuous-descriptor, event-corroborated design. For #12: its hard dependency arrives only on 26 Nov so it cannot distract from Phase 1, and Smart Tagging is free supervision for “what counts as a moment”. Against: it is the sponsor’s own product category, and “moment” is subjective — exactly where gimmicks live.
  • “Ball absent → D” vs “ball absent → X”. The advisors contradict each other and both are wrong: B’s version is arithmetically dead (≈67 k ball-absent frames vs only 2,934 graded D frames in H1), D’s version is an unverified bet on 40 % of the score. The resolution is a third behaviour — infer deadness from evidence (absence + no player near the last ball position + low player speed + set-piece tag + known half boundaries) and only then label D.
  • Ship early vs perfect-late. SUBMISSION.md states one response per team, editable, last response before the deadline is the one scored — so a schema-correct baseline submitted ~14 Nov is free optionality, not a wasted day.

⚠️ Blind Spots & Hidden Risks Uncovered by Peer Review

  • The X-policy on ball-absent frames is the single highest-leverage unknown in the project — it governs 40.69 % of graded frames. It must be certified with the organisers, not guessed. Five advisors invented five confident, mutually contradictory policies.
  • Resubmission semantics must be confirmed before the strategy is fixed. If only one submission counts, an early probe CSV could destroy the entry; if the last response counts, probing is free.
  • The public repo cannot contain the licensed ATD, so “regenerates byte-for-byte” needs a documented, checksummed data-acquisition step (download + SHA-256 manifest) — unplanned by all five advisors.
  • A formation demo on one match is ~5 events; two false positives kills it. The demo only becomes credible on 10 matches (≈40 events) — another reason the project cannot be built before 26 Nov.
  • Swap-in vs tactical reshuffle is unresolvable without event data: a vacated slot plus an arriving substitute looks exactly like a reshuffle. The fix is to require event corroboration before declaring a change — which only Phase 2 makes possible.
  • Your tracker slots are a gift, not a bug. Track 44 never observed, Track 22 on 44 frames — so per-slot artefacts are provably tracker artefacts, not signal. Use that when a coefficient looks surprising.

🏛️ Advisor Deliberations

Advisor A — The Contrarian / Red Team hypothesis breaker
  1. Validation void (kill shot). A formation detector has no ground truth anywhere. The bundle contains no formation labels, and the rules ban hand-labelling this match “for any purpose” — including validation. The 5-minute public truth that makes possession measurable is separately banned from tuning. Possession has a floor (0.2433) and a leaderboard; “formation change” has neither. The first jury question is “how do you know 4-2-3-1 became 4-3-3?” and the honest answer is “we thresholded a shape metric” — a heuristic demo, not a system.
  2. The dependency runs backwards. Formation does not extend the possession engine; possession would feed it. Formation work buys zero Phase 1 score, and Phase 1 is the only thing that ranks you. Worse, the silent sink most teams underestimate: organisers re-run the repo byte-for-byte, so pin CPU, seeds and lockfiles — one GPU-nondeterminism bug can fail a correct solution on 17 Nov.
  3. Identity-free guts the demo. 46 slots used erratically (Track 44 never observed; Track 22 on 44 frames), no IDs → you can compute team shape and nothing per-player. “Change detection” degenerates into thresholded noise on one wide-angle camera with rectilinear homography (depth error grows away from centre). Set pieces are 5 s/35 s windows, so the event timeline is ±seconds fuzzy before you even start.
  4. Ten matches is a demo reel, not a training set. No list item can be an ML model. Pick a system, and prefer one whose load-bearing input only arrives on 26 Nov — event data with exact timestamps — which is precisely what fixes the fuzzy-window problem.
  5. Jury gimmick. A formation chart is a commodity view; Metrica is a club-facing analytics vendor, so a formation pitch may read as re-implementing the sponsor’s product. Prizes are travel, shirts and experience — reputational, not commercial.

Recommendation: #12 rebuilt as an identity-free tactical-context engine; keep formation as one panel inside it. Do not commit the project today — only possession commits now; choose the topic on 26 Nov with the data in hand.

Advisor B — The First Principles Thinker reframes the gate

Phase 1 is a filter, not a prize — automatic scoring, no jury, one binary outcome (top 20 of 4,000+). And the project cannot be built before 26 Nov: the 10-match tracking+event dataset doesn’t exist until then. So pre-17-Nov idea work has no data behind it. Spend 6 days ~85 % on the possession pipeline, 0 % on the idea.

Attacking the hypothesis: the synergy claim is mostly false. Formation isn’t a possession phenomenon — it needs the same ATD, not your spells. The one real bridge is Metrica’s own labels: 638 tagged instances with mirror-paired codes — a provided, non-hand-made validation set for “does the shape index separate BUILD UP from PROGRESSION?”.

Identity-free is a non-issue — 46 persistent slots are pseudo-identities. Good for feasibility; but it proves the project doesn’t need Phase 1’s asset.

What breaks is legitimacy, not feasibility. Analysts will demand ground truth for “4-3-3” that doesn’t exist. A hand-made taxonomy is the gimmick. Fix: continuous descriptors (width, line height, compactness, centroid, stretch, PPDA proxy) + change-point detection; formation names only as an overlay; attribute each change to exogenous events (subs, cards, phase) so output is detected and explained.

Unimpressive: a formation confusion matrix; “unknown” on 4-1-4-1; LLM narration (also rule-barred through cloud).

Hard constraint: Phase 2 guarantees only tracking + events → the project must be a function of those alone. That kills Highlights (needs video), Comeback Probability (needs calibrated history), Sub/Red Card Impact (10 matches, n ≈ 5).

Phase 1 recipe: nearest-slot-to-ball; sustained ball-absent runs → D (the 138.6 s / 221.5 s gaps are stoppages) but never D at halftime’s 94 % ball-present warm-up; min spell ≈ 2 s; merge same-team gaps; abstain to X when unsure (free inside a spell, costly across hand-overs). Resolve slot→team provenance in hour one — it swings difficulty an order of magnitude. Budget a full day for byte-for-byte reproduction.

Verdict: #8 with #7 as read-out, reframed as live shape+possession intelligence; build the label-free engine 17–26 Nov with a batch harness so 10 matches ingest in hours on 26 Nov.

Advisor C — The Expansionist / Strategist peer-review winner

Verdict: #12 rebuilt as an automatic tactical-moment engine, with possession spells as its backbone.

Formation breaks on identity and arithmetic: identity-free geometry gives shape, not roles. “Formation change” is a role-level event (the 8 advancing, the striker dropping); with 46 anonymous slots — Track 44 never observed, Track 22 seen on 44 frames — role assignment is unsolvable. The deliverable degenerates into a line-chart of 11 dots, a broadcast commodity. Worse, it is an n=1 claim: one match, one opponent. Nothing generalises until 26 Nov, so it must be rebuilt in January anyway — it does not compound with Phase 1, it competes for the same hours.

The binding risk is Phase 1, and it is not what the list implies. The ball is missing on 40.69 % of graded frames, so you never “detect” possession — you infer it from geometry (cluster the 46 slots into two persistent spatial clusters, recover the 24/22 side split, then nearest-player/cone containment) and carry calibrated uncertainty. That estimator is the reusable IP, not the CSV. Treat it as a library. Traps to hard-code: halftime (ball present 94.07 %, ~12.5 players), 2,934 graded D frames, every throw-in N/A, 34 % of broadcast frames non-play (use tactical only). Under one-to-one temporal-IoU matching, over-segmentation is punished twice — merge aggressively, never emit X near a handover, bias boundaries a few frames early. Tune on hand-labels of other matches (legal); the public 5-minute truth is poisoned.

Why #12 wins: the 638 Smart Tagging instances are free supervision for “what counts as a moment” — the asset nobody else will mine. Every clip traceable to a spell, every label auditable, organisers can re-run the repo. Also the umbrella: substitutions, red-card aftermaths and comeback arcs ship as downstream add-ons.

Higher-order: you exit with a licensed-clean, paper-shaped corpus — a 199k-frame possession benchmark plus tactical-moment supervision — and Barça’s obvious future partner. The jury calls gimmick what it always calls gimmick: a reel without provenance, a formation chart without generality, a probability model without calibration. Ship the ones with a baseline.

Advisor D — The Outsider / Domain Skeptic framing breaker

Verdict: the topic is defensible; the framing is wrong. A Formation Change Detector is not a project layered on top of a possession pipeline — it is the pipeline’s first stage. So 100 % of the next 6 days goes to the possession engine, and the March artefact starts 26 Nov.

What breaks: the provided match cannot validate a formation detector — hand labels on that match are forbidden, so your only full-match supervision is Smart Tagging’s 638 instances with 5 s/35 s windows, and you have no substitution events until 26 Nov. Without events, a vacated slot plus an arriving substitute is indistinguishable from a tactical reshuffle — the detector’s core false-positive source, and a coach will kill the demo on it. Also: 24 slots for a side with an 18-man matchday squad, Track 44 never observed, ~12.5 warm-up players at halftime — you must infer the on-pitch set before you can count lines. And the ball is missing on 40.69 % of graded frames, so every ball-relative metric (line height vs. ball, compactness, press trigger) dies on two of every five frames. Only shape geometry survives, and shape is phase-conditional: “4-3-3” is a build-up shape or a defending shape, and phase labels come from those same 638 coarse codes.

What a Barça jury discounts: a formation heatmap on one match is what a club already produces from staff video — N=1, replication. “Comeback probability” and “expected points” are commodities; “schedule difficulty” would embarrass you. Identity-based ideas (Player Value, AI Scout, Similarity, Substitution Impact) are structurally dead — no identities in tactical ATD; Phase 2 promises tracking + events, not identities.

Where effort goes: now → 17 Nov, pipeline only but built geometry-first — slot→team assignment, team-shape features, phase segmentation from the mirrored codes, then spells. One artefact serves both deadlines. Exploit the label asymmetry: X is forward-filled so abstaining inside a possession is nearly free, while a wrong D breaks the spell. 26 Nov → 14 Jan: build the project on 10 matches, using the hand-label escape hatch (labels on any match other than the provided one are allowed) to gold-standard formations — converting “n=1” into a measured claim.

Advisor E — The Executor / Pragmatic Engineer execution reality

Verdict: keep #7 + #8, throw away the sequencing. The pick survives on execution grounds — but the plan for it is backwards.

Why the pick holds: it is the only listed idea that needs nothing but the ATD + homography. #4/#12 require reading the scoreboard overlay, which means local vision (competition data can’t go to third-party cloud LLMs); #2/#3/#6/#9/#10 need identities and events the Phase-1 bundle lacks, and n=1 cannot support them; #13/#11/#5 are spreadsheets. And shape is ball-independent — the 40.7 % missing-ball rate that will wreck any event-detection idea doesn’t touch formation at all.

Where effort goes: now–17 Nov (5 days): 100 % possession pipeline, zero formation code. Three deliverables: CSV; byte-reproducible repo (lockfile, sorted iteration, fixed float format — budget a full day, most teams blow this); 2-page technical doc. One parallel background task only: pull 2–3 public tracking matches with known formations (Metrica sample data) as a validation set — legal, since hand labels are banned only on this match.

17–26 Nov gap: de-risk, don’t build. Parse those external matches, hand-label formations (allowed elsewhere), build the line/role clusterer. Go/no-go on 26 Nov: if line assignment can’t hit ~85 %, pivot. 26 Nov–14 Jan: build on the 10 pro matches; detect changes with minimum-dwell-time plus per-player displacement thresholds; ship a demo the jury can verify by watching video.

What breaks in the hypothesis: (1) “identity-free” covers teams, not roles — assigning 22 on-pitch slots to lines is the project, and it’s what a Barça analyst attacks: “4-2-3-1 or 4-3-3? which midfielder is the pivot?” Geometry alone cannot answer. (2) “Visually demonstrable live” cuts both ways: ~5 changes in one match means two false positives kills the demo. Forty events across 10 matches is the real demo. (3) Exploit Smart Tagging — 638 paired-mirror intervals are coarse team-possession supervision; get organiser sign-off in writing first.

Rollback: keep formation a module, not the spine. #12 remains the January fallback — it rides the event engine Phase 1 already builds.

🔍 Anonymous Peer Review

Strongest argument → Response C

Response C is strongest. Its core claim: with the ball missing on 40.69 % of graded frames, possession is never detected but inferred from slot geometry with calibrated uncertainty — and that estimator, not the CSV, is the reusable IP, so build a library and choose the topic on 26 Nov. It alone ties audited facts to scoring math: under temporal-IoU 0.3–0.7, over-segmentation is punished twice (merge aggressively; never emit X near a handover); X forward-fills only within a half, so abstention inside a spell is nearly free; and it enumerates traps — halftime 94.07 % ball-present / ~12.5 warm-up players, 2,934 D frames.

The rivals: A’s “no formation ground truth” is true but only disqualifying — no mechanism, no winner. B’s “Phase 1 is a filter” is right, yet its verdict (commit #8) contradicts it, and its 638-instance validation set ignores 5 s/35 s coarseness. D’s substitute-vs-reshuffle ambiguity is the sharpest single attack on formation, but D never says what to build or how to score. E’s ball-independent shape is real, but E’s own findings (roles unresolvable, ~5 changes/match) sink its verdict; E lands on C’s plan.

Fatal blind spot → Response D — the X-policy

Its rule “emit X when the ball vanishes” assumes X is a free, safe abstain class. Nothing in the audit defines X, its forward-fill behaviour, or how the grader scores it — and that one choice governs 40.69 % of graded frames. If the truth there is H/A (the spell continues through occlusion) or D, your X-predictions are false positives and H/A recall collapses; mean F1 lands at or below the 0.2433 floor and you are out of the top 20 of 4,000+. Response B asserts the opposite rule (“sustained ball-absent runs → D”) — the two contradict, which proves nobody has settled it. B’s version is already arithmetically dead: 40.69 % missing ≈ 67 k frames vs only 2,934 graded D frames in H1, so ball-absent ≠ D.

Cheapest retirement (½ day, before any modelling): (1) ask organisers/Metrica for the D/X label schema; (2) align the 638 Smart Tagging windows to the ball-visibility timeline and read halftime (ball present 94.07 %, no play) as free probes; (3) submit two cheap probe CSVs (X-on-absent vs H/A-continued) and compare leaderboard F1.

Missing consideration → the grader’s labelling contract

The metric is not “detect possession”; it is “reproduce the organisers’ label function” (spell matching, temporal IoU 0.3–0.7). Five advisors each invented a confident policy — B: ball-absent→D; D: ball-vanishes→X; C: never emit X near a handover — and they contradict each other, so at least two are wrong. A swapped H/A or inverted D/X doesn’t cost a few points; it collapses F1, you miss the top 20, and every project argument becomes moot.

Same blind spot: a public repo cannot ship the licensed ATD, so byte-for-byte regeneration needs a checksummed download path — unplanned by all five.

Why it dominates: Phase 1 is binary and gates everything after it. Project choice only pays if you pass.

Council must decide: (1) owner and deadline for certifying the contract; (2) a schema-correct baseline submitted ~14 Nov as insurance; (3) the project only afterwards, under the rule that it must survive merely mediocre possessions.

Chairman’s note: the reviewer is right about the consequence and partly wrong about the source. The file contract (header, row count, frame order, label alphabet, X scoring, forward-fill, tie-breaks, graded windows, resubmission semantics) is fully documented in the repo — I read it. What is genuinely undocumented is the dead-ball onset rule: does D start at the infringement, the whistle, or the corrected tracking’s dead flag? That is open issue #31, still unanswered. So the certification task is narrower and cheaper than feared — but it is now, not later.
